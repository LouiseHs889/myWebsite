Docker

使用Docker 的目的:

在開發的時候，常常明明在自己的電腦上面可以正常運行，但部屬到公司或是其他環境後，可能因為 JAVA 的版本不同、套件或是對方的電腦環境設定不同而出現錯誤，Docker 可以幫助我們降低這類環境差異所造成的問題。它將程式與所需的執行環境封裝在 Image 中，讓程式可以以較一致的方式執行。

以下將以 Java 專案為例，透過實際操作，完整介紹如何將 Java 應用程式部署到 Docker Container（容器）中。

整體流程:

先產生JAR 檔⇒透過Dockerfile 建立 docker image ⇒使用docker run 產生並執行 docker container。

  1. 先建立一個 spring boot project ( 以下以 maven 打包為例 )
  2. 建立好後先在 project 目錄底下建立一個 Dockerfile
  1. Dockerfile 內容:
  • FROM eclipse-temurin:17-jdk : 以 java 17 作為這個container image 的基礎
  • WORKDIR /app : 代表這個 container 裡面的工作目錄
  • COPY target/*.jar app.jar : copy 專案底下 的 jar 檔到 container 工作目錄底下，這裡的app.jar 不一定要取這個名稱，也可以取其他名字，但要跟下面的 entrypoint 裡面的jar 檔名稱一樣
  • ENTRYPOINT [“java”, “-jar”, “app.jar”] : Container 啟動時執行：java -jar app.jar
  1. 接下來要先把 spring boot 打包，再放到docker
  1. 建立 Docker Image
  • Dockerfile 透過 docker build 這個指令 把他變成 docker image，因此my-spring-app 就是 docker image 的名稱
  • 這句指令最後的那個 “ . “ 一定要加上，代表把「目前這個目錄」當作 Docker build context 傳給 Docker。
  • Build context = Docker 在 docker build 時「可以拿來建 Image 的檔案範圍」
  • 把目前 my-docker-test-project/ 當作 Build context ，docker 在 build 的時候可以使用 my-docker-test-project/ 這個目錄底下的檔案
  • copy 能拿的檔案，是以 build context 為範圍，不是以 Dockerfile 所在位置為範圍，所以不能拿build context 這個範圍外的檔案。
  1. 用 Image 建立 Container

這時候才真正產生並啟動 Container

-p 9090:8080 : 意思是自己電腦 9090 port 收到的 request，轉到 Container 的 8080 port

所以你開 http://localhost:9090/hello 就會得到事先建立好的 /hello 這個api 對應到的內容

補充:

gradle 的話:

./gradlew clean 會把 build/整個刪掉

./gradlew build: build/libs/xxx.jar
